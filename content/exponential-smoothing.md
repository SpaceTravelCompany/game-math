## 소개

지수 감쇠(Exponential Smoothing)는 프레임 속도에 독립적으로 값을 목표로 부드럽게 수렴시키는 기법이다. 게임에서 카메라 따라가기, 회전 감쇠, 색상 전환, 수치의 점진적 변화 등 가장 널리 쓰이는 부드러움 처리 방식이다.

> **핵심**
> 지수 감쇠는 "매 순간 남은 거리의 일정 비율만큼 이동"한다. 그 비율이 $1 - e^{-r\,dt}$로 프레임 독립적이다.

> **참고**: 《벡터 보간》 §1에서 다룬 프레임 독립 Lerp, 《회전 & 보간》 §7의 쿼터니언 감쇠, 《벡터 보간》 §5의 SmoothDamp는 모두 이 지수 감쇠 패턴의 변형이다. 본 문서에서는 이 패턴을 통합적으로 설명한다.

## 1. 프레임 독립 보간의 필요성

고전적인 Lerp는 프레임 속도에 따라 결과가 달라진다:

```text
// 프레임 의존적: 60fps와 30fps에서 속도가 다름
position = lerp(position, target, 0.1f);
```

60fps에서 1초 동안: $t$가 60번 적용 → $(1 - 0.1)^{60} \approx 0.0018$ (99.8% 수렴)

30fps에서 1초 동안: $t$가 30번 적용 → $(1 - 0.1)^{30} \approx 0.042$ (95.8% 수렴)

같은 1초인데 30fps에서는 목표에 덜 도달한다. **프레임이 낮을수록 움직임이 더뎌지는** 문제다.

```text
    목표
    ↑
    │  ─── 60fps
    │  - - 30fps
    │  (30fps가 더 느리게 수렴)
    └─────────→ 시간
```

## 2. 공식과 직관

### 프레임 독립 지수 감쇠

$$t = 1 - e^{-r \cdot dt}$$

```text
// 프레임 독립
float t = 1.0f - exp(-rate * deltaTime);
position = lerp(position, target, t);
```

### 연속 붕괴 모델의 직관

연속적인 시간에서, 매 순간 "남은 거리의 일정 비율"만 사라진다고 상상하자:

$$\frac{d}{dt}\,(\text{remaining}) = -r \cdot \text{remaining}$$

이 미분방정식의 해는:

$$\text{remaining}(t) = \text{remaining}_0 \cdot e^{-r\,t}$$

즉, $dt$ 시간 후에는 $e^{-r\,dt}$ 배만큼의 거리가 남고, $1 - e^{-r\,dt}$ 만큼 이동한 것이다.

```text
    남은 거리 비율
    1.0 ┤ ████
    0.5 ┤    ████
    0.25┤       ████
    0.125┤         ████
        └─────────────→ 시간
        매 순간 절반씩 (r=ln2)
```

### Half-Life (반감기)

목표까지의 거리가 절반으로 줄어드는 데 걸리는 시간:

$$t_{1/2} = \frac{\ln 2}{r}$$

예: $r = 2$ → 반감기 $\approx 0.347$초 (약 347ms마다 절반)

## 3. 왜 프레임 독립인가

`dt`가 곱해져 있으므로, 어떤 프레임 속도에서도 동일한 시간이 지나면 동일한 비율로 수렴한다:

$$(1 - t)_{\text{after 1 sec}} = e^{-r \cdot 1}$$

즉, 60fps든 30fps든 1초 후 남은 비율은 동일하게 $e^{-r}$이다.

```text
// 60fps: dt=1/60 → 60번 반복
(1 - (1 - e^{-r/60}))^60 = e^{-r}

// 30fps: dt=1/30 → 30번 반복
(1 - (1 - e^{-r/30}))^30 = e^{-r}   // 같음!
```

**주의 (흔한 오해)**: $1 - e^{-r\,dt}$는 미분방정식 $\dot x = -r\,x$의 **정확한 닫힌 해**에서 유도된 계수로, $dt$ 크기와 무관하게 정확하다(Taylor 절단 오차가 없다). 오차와 오버슈트는 이를 근사한 $t \approx r\,dt$를 쓸 때만 생긴다 — 특히 $r\,dt > 1$이면 근사 계수가 1을 넘어 lerp이 목표를 지나쳐 오버슈트한다.

### 극단/수치 처리

- **$dt = 0$**: $t = 1 - e^0 = 0$ → 값이 그대로 유지된다(자연스럽게 안전).
- **작은 $r\,dt$ (자리손실)**: $1 - (1 - \varepsilon)$ 꼴의 catastrophic cancellation을 피하려면 $1 - e^{-r\,dt}$ 대신 $-\mathrm{expm1}(-r\,dt)$를 쓴다(표준 수학 라이브러리가 제공).
- **큰 $dt$**: $t \to 1$ → 한 프레임에 목표에 도달한다. 고속 이동·카메라 급추종 시 채터링/튀김이 보일 수 있으니 rate 상한이나 목표 smoothing을 고려한다.

**이산 계수에서 환산**: 매 프레임 `lerp(a, b, t₀)`을 적용하는 프레임 의존 코드와 동치로 만들고 싶으면, 《벡터 보간》 §1의 $(1-t_0)^{dt \cdot 60}$에서:

$$r = -60\,\ln(1 - t_0)$$

## 4. 응용

### 카메라 따라가기 (Smooth Follow)

```text
// 지수 감쇠로 카메라가 플레이어를 부드럽게 따라감
float rate = 5.0f;  // 클수록 빠름
float t = 1.0f - exp(-rate * dt);
camera.position = lerp(camera.position, player.position, t);
```

**쿼터니언 회전 감쇠** (《회전 & 보간》 §7):

```text
float t = 1.0f - exp(-rate * dt);
camera.rotation = slerp(camera.rotation, targetRotation, t);
```

### 색상/수치 부드러운 변화

```text
// HP 바가 천천히 줄어듦 (체력 감소 효과)
float rate = 3.0f;
float t = 1.0f - exp(-rate * dt);
displayHP = lerp(displayHP, actualHP, t);

// 조명 밝기 부드러운 전환
float t = 1.0f - exp(-2.0f * dt);
light.intensity = lerp(light.intensity, targetIntensity, t);
```

### 목표값이 연속적으로 변할 때

고정된 목표가 아니라 매 프레임 움직이는 목표(예: 다른 캐릭터)를 따라갈 때도 동일 공식이 적용된다:

```text
// 움직이는 목표 추적 (지연 효과)
float t = 1.0f - exp(-4.0f * dt);
smoothedPos = lerp(smoothedPos, currentPos, t);
```

## 5. 지수 감쇠 vs Lerp vs Spring

| 특징 | 지수 감쇠 | 고전 Lerp (고정 t) | 스프링 (Spring) |
|------|----------|-------------------|----------------|
| **프레임 독립** | ✅ | ❌ | ✅ (sub-step 필요) |
| **오버슈트** | 없음 | 없음 | 가능 |
| **파라미터** | rate 1개 | t 1개 | k, c, m 3개 |
| **관성 효과** | 없음 | 없음 | 있음 |
| **안정성** | 항상 안정 | 항상 안정 | dt 너무 크면 발산 |
| **계산 비용** | 매우 낮음 | 매우 낮음 | 중간 |

### 언제 무엇을 쓸까

- **단순 추적** → 지수 감쇠. 가장 가볍고 안정적.
- **관성/튕김이 필요하면** → 스프링. 무기 복원, 탄성.
- **프레임 독립이 필요 없고 단순하면** → 고정 t Lerp (UI 애니메이션 등).
- **목표가 급변할 때** → 지수 감쇠. overshoot 걱정 없음.

> **실전 팁**: rate 값을 정할 때 반감기를 기준으로 생각하자. "1초 안에 90% 수렴"이 목표라면 $r = -\ln(0.1) \approx 2.3$이다. $r = 3$이면 약 0.77초에 90% 수렴한다.
